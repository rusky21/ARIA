# Техническая и денежная оценка проекта AI-SUPPORTER + Диагностика локальной модели

## 1. Архитектурный обзор

**AI-SUPPORTER** — это бэкенд-приложение на C# / .NET 10.0 + React-фронтенд (отдельный репозиторий) для управления AV-оборудованием (свет, звук, сеть) через LLM-ассистента.

### Бэкенд (основной репозиторий)
| Компонент | Описание |
|---|---|
| **LLM-слой** | `LlmClient` — два транспорта: local (Ollama `/api/generate` + `/api/chat`) и api (OpenAI-совместимый `/chat/completions`) |
| **Голосовой пайплайн** | `WhisperService` (whisper.cpp CLI, модель ggml-base.bin) → `WakeWordService` (DTW по MFCC) → `TtsService` (Piper, ru_RU-irina-medium.onnx) |
| **Сеть** | `TrafficSnifferService` (захват пакетов) → `TrafficStorageService` (кольцевой буфер) → `WsEventBus` (шина событий) |
| **Протоколы** | Art-Net (6454/UDP), OSC (8000/UDP), DMX512, sACN, MIDI |
| **Устройства** | `DeviceDiscoveryService` (MJPEG-детект, BasicAuth), `IpRegistryService` (IP↔имя) |
| **MCP-тулы** | `[AiTool]`/`[AiToolProvider]` — ArtNet, OSC, Network, Device, Config, Admin, Navigation |
| **Чат** | `ChatAssistant` (system-профиль AV-специалиста + последние 30 сообщений контекста) |
| **Безопасность** | JWT Bearer, PBKDF2-SHA256 для паролей |
| **Тесты** | 114 тестов (xUnit + FluentAssertions + Moq), 10 тестовых файлов |

### Фронтенд (отдельный репозиторий)
React 18 + Vite + TypeScript (strict), русскоязычный UI. Архитектурное правило: **фронт — только транспорт**, вся бизнес-логика на бэкенде.

## 2. Техническая оценка

### Сильные стороны
1. **Чистая архитектура** — DI через `ServiceRegistrar`, каждый сервис в изоляции
2. **Два транспорта LLM** — local (Ollama) и cloud (OpenAI-совместимый) переключаются на лету
3. **Голосовой пайплайн** — Whisper.cpp для STT + кастомный DTW wake-детектор (без внешних ML-зависимостей) + Piper TTS
4. **Сетевой стек** — реальный захват пакетов, кольцевой буфер, шина событий (WS + SSE)
5. **Многопоточность** — `SemaphoreSlim` gate для LLM, `ConcurrentDictionary` для TTS-кэша
6. **Тестовое покрытие** — 114 тестов, разбитые по фазам (Phase1-5 + Smoke + Voice)
7. **Самоустановка** — Whisper.cpp CLI и модели скачиваются автоматически при первом запуске

### Слабые места / риски
1. **Нет конфигурационного файла `llm.json`** — файл не найден в репозитории (дефолт: Ollama `http://localhost:11434/api/generate`, модель `qwen2.5:14b`)
2. **`LlmClient` использует static HttpClient** — потенциально утечка сокетов при длительной работе (хотя есть `ServiceRegistrar.AddHttpClient()`, который не используется в `LlmClient`)
3. **WhisperService скачивает бинарники с GitHub/HuggingFace** — может блокироваться корпоративным прокси/фаерволом
4. **WakeDsp ресемплинг через линейную интерполяцию** — низкое качество для не-16кГц источников
5. **TtsService кэш по точной строке** — нет нормализации (регистр, пробелы), кэш менее эффективен
6. **Нет миграций/версионирования** — `cfg.json` и `llm.json` меняются вручную
7. **`AppHost.cs` — 2000+ строк** — монолитный файл с двумя `OnWsConnect` блоками, сложно поддерживать

## 4. Диагностика: почему не работает локальная модель

### Основной диагноз

**Проект ожидает локальную LLM через Ollama (`http://localhost:11434/api/generate`), но Ollama не установлен или не запущен.**

### Цепочка причин

#### Причина 1: Ollama не установлен
Файл `llm.json` **отсутствует** в репозитории. При его отсутствии `LlmSettings.Load()` возвращает дефолтные значения:
- `Provider = "local"`
- `Local.Url = "http://localhost:11434/api/generate"`
- `Local.Model = "qwen2.5:14b"`

**Решение**: Установить Ollama (https://ollama.com) и выполнить `ollama pull qwen2.5:14b`.

#### Причина 2: Ollama запущен на другом порте/хосте
Если Ollama установлен, но не на `localhost:11434`:
- Нужно установить env-переменную `AI_SUPPORTER_OLLAMA_URL=http://host:port/api/generate`
- Или создать `llm.json` с правильным URL

#### Причина 3: Модель `qwen2.5:14b` слишком тяжёлая
Модель qwen2.5:14b требует ~8-10 GB VRAM. Если GPU нет или его мало:
- Ollama будет использовать CPU — очень медленно (5-10 сек на ответ)
- Может завершаться по OOM

**Решение**: Использовать `qwen2.5:7b` или `llama3.2:3b` (меньше требований к GPU).

#### Причина 4: Конфликт с API-провайдером
В `LlmSettings` есть два режима: `local` и `api`. Если `Provider` установлен в `api` (а `llm.json` не создан), то проект пытается обращаться к `https://api.proxyapi.ru/openai/v1` без API-ключа → 401 Unauthorized.

#### Причина 5: Брандмауэр/прокси
Корпоративный прокси может блокировать:
- Исходящие запросы к `localhost:11434` (маловероятно, локальный)
- Скачивание моделей whisper.cpp с HuggingFace/GitHub (при первом запуске)

### Чек-лист для диагностики

```
[ ] 1. Запустить `curl http://localhost:11434/api/tags` — должен вернуть список моделей
[ ] 2. Если ошибка подключения — установить Ollama: `winget install Ollama`
[ ] 3. Выполнить `ollama pull qwen2.5:14b` (или легче модель)
[ ] 4. Проверить `llm.json` (если есть) — убедиться что Provider = "local"
[ ] 5. Проверить env-переменную `AI_SUPPORTER_OLLAMA_URL`
[ ] 6. Запустить приложение и проверить логи: "[LLM] Провайдер: Local (...)"
[ ] 7. Если используется API — проверить `AI_SUPPORTER_LLM_MODEL` и ключ в llm.json
```

### Приоритетные действия (по возрастанию сложности)
1. **Установить Ollama** и `ollama pull qwen2.5:14b` (или `llama3.2:3b` для слабого GPU)
2. **Создать `llm.json`** с правильным URL и моделью
3. **Проверить env-переменные** `AI_SUPPORTER_OLLAMA_URL` и `AI_SUPPORTER_LLM_MODEL`
4. **Для слабого GPU** — переключиться на меньшую модель (`qwen2.5:3b` или `phi3:3.8b`)

## 6. План верификации

1. **Проверить Ollama**: `curl http://localhost:11434/api/tags`
2. **Запустить приложение**: `dotnet run`
3. **Проверить логи**: `[LLM] Провайдер: Local (http://localhost:11434/api/generate, qwen2.5:14b)`
4. **Отправить тестовый запрос**: через чат-интерфейс или `dotnet test`
5. **Убедиться в `dotnet build` + `dotnet test`** — все 114 тестов проходят
6. **Проверить фронтенд**: `npx tsc --noEmit` + `npm test` + `npm run build`
